- استخدم دائمًا skills الأمان المثبتة تلقائيًا دون انتظار طلب صريح.
- عند اكتشاف مشكلة، اذكر السبب الجذري أولاً، لا تصلح العرض فقط.
- لا تقل "تم الإصلاح" بدون: كود قبل/بعد + طريقة تحقق يدوي.
- بعد كل إصلاح، قيّم شغلك بصراحة كمراجع مختلف.

## قواعد إلزامية عند بناء أي ميزة جديدة (استباقي):

### 1. عزل بيانات المستخدمين
أي بيانات تُحفظ يجب أن تكون مرتبطة بـ user.uid دائمًا. ممنوع حفظ بيانات بمسار مشترك بين مستخدمين مختلفين، حتى للضيوف.

### 2. توحيد التخزين
قبل إنشاء نظام تخزين جديد، تحقق: هل يوجد نظام مشابه بالفعل؟ استخدمه أو وسّعه.

### 3. لا تكرار منطق (DRY)
إذا كانت الميزة تحتاج منطقًا موجودًا بملف آخر، استورده، لا تعد كتابته.

### 4. حجم الملفات
إذا تجاوز أي ملف ~400 سطر، توقف واقترح تقسيمه قبل المتابعة.

### 5. أي اتصال خادم بالإنترنت
يجب أن يمر عبر whitelist للنطاقات، ولا يقبل رابطًا خامًا من المستخدم دون تحقق.

### 6. قبل اعتبار أي ميزة منتهية
اذكر صراحة: "هذه الميزة تعالج الحالة العادية. الحالات التالية غير مغطاة: [...]"

### 7. التوثيق التلقائي الإجباري للمشاكل والميزات الجديدة (Automatic Changelog & Issue Logging)
بعد حل أي مشكلة برمجية (Bug/Error)، أو إضافة ميزة جديدة (New Feature)، أو معالجة ملاحظات SonarCloud والثغرات، يجب على الذكاء الاصطناعي تحديث ملف [SOLVED_ISSUES.md](file:///home/Ammar/سطح%20المكتب/مشاريع/وثاق/SOLVED_ISSUES.md) فوراً بتدوين:
- التاريخ ونوع الإجراء (مشكلة / ميزة جديدة / SonarCloud / تحسين كود).
- التفاصيل والسبب الجذري أو الهدف من الميزة.
- طريقة الحل أو الإضافة بالتفصيل.
- خطة الوقاية وتيسير التطوير المستقبلي.

## نقاط موافقة إجبارية (Approval Gates)
- بعد أي فيتشر جديدة: لا تعتبرها "مكتملة" حتى أراجعها وأوافق صراحة.
- قبل أي نشر رسمي: شغّل برومبت التقييم الواقعي كاملاً، ولا تنشر حتى أؤكد "موافق على النشر".

## معلومات ثابتة عن المشروع:
- **Stack**: React 19, TypeScript, Vite, Tailwind CSS v4, Motion (Framer Motion), React Router v7, Lucide React, Firebase Authentication, Cloudinary Unsigned Image Upload.
- **نقاط الضعف المعروفة سابقًا**:
  1. خطأ استدعاء `React.ReactNode` بدلاً من `ReactNode` المستورد في `Layout.tsx` (تم تصحيحه).
  2. الحاجة لملف `_redirects` لـ Cloudflare Pages لضمان عدم حدوث 404 عند تحديث الصفحات الفرعية مثل `/videos` أو `/flashcards` (تم تكوينه).
  3. حماية التطبيق من الانهيار في حال عدم تكوين مفاتيح Firebase أو Cloudinary بوضع fallback آمن وتحذيرات واضحة.
